# 增补假绿事故复现夹具（2026-11-22）

## 事故现象

在保证金笼页面点击「增补」后：

1. 作业票（`topup_jobs`）新增成功，页面提示成功；
2. 笼面 `cages.amount / cages.available` 纹丝不动；
3. 当事人账户 `bond_accounts.frozen` 纹丝不动（可用资金未真正冻入笼内）；
4. 对账互证灯仍亮绿——因为账实两侧都没动，恒等公式自然恒等，属于**假绿**。

## 根因

`backend/topup_svc.py` 为空桩：只向 `topup_jobs` 插入一条作业票并写审计，
既不抬高笼面总额/可用，也不增加账户冻结。详见 `docs/decisions/增补扩笼纪要.md`。

## 夹具口径（tests/test_topup_expand.py）

- 种子冻结笼：`CG-P-EAST-001`（当事人 P-EAST，种子冻结 120000）。
- 增补 30000 后正确口径应为：
  - 笼总额 120000 → 150000，笼可用同步 → 150000，笼代 1 → 2；
  - 账户冻结 120000 → 150000，账户余额不变（钱只在可用→冻结间搬）；
  - 对账：`可用+拨付+罚没=笼总额` 仍平衡，且 `账户冻结=活笼可用合计`。
- 两条失败测先行（TDD 见红）：
  1. `test_topup_must_expand_cage_and_freeze_account`：增补未扩额即失败；
  2. `test_two_writers_topup_same_cage_lock_contention`：双人同补须抢笼锁，后到只留争用痕。
